# Тесты

Сквозные тесты гоняют собранный сайт через HTTP, как это делают клиент RustDesk,
браузер и внешние сервисы. Каждый набор получает свежий сайт, чистое хранилище
и заглушки: ЮKassa, VK ID, Telegram, почтовый сервер (`tests/fakes`).

```bash
npm run build
npm test                 # хранилище — JSON-файл
npm run test:pg          # Postgres: нужен TEST_DATABASE_URL
node tests/run.mjs autopay monitoring   # отдельные наборы
```

| Набор | Что проверяет |
|---|---|
| `clientapi` | API клиента RustDesk: вход, токены, адресная книга, heartbeat, аудит |
| `features` | блокировка и удаление аккаунтов, книги, команды, тревоги, журналы, команды сервера, веб-клиент, VK ID |
| `email-verify` | подтверждение почты, повторное письмо и лимит, запрет оплаты до подтверждения, VK ID |
| `limit-upgrade` | суточный лимит, одновременные сессии, доплата за повышение тарифа |
| `auth-history` | восстановление пароля, лимиты писем, история подключений |
| `attachments` | обращения в поддержку со снимками экрана |
| `autopay` | автопродление и чеки ЮKassa, отказы банка, второй чек, гонки |
| `relays` | ретрансляторы: список в hbbs, чередование, отказ узла, перезапуск hbbs |
| `monitoring` | проверки, оповещения, инциденты, плановые работы, сторож |

`features`, `relays` и `monitoring` работают с настоящими hbbs и hbbr —
сборкой с патчами RemIT. Пути к ним задаются `HBBS_BIN` и `HBBR_BIN` (как
собрать — `.github/workflows/ci.yml`, шаг «hbbs и hbbr с патчами»). Без них эти
наборы пропускаются.

В CI (`.github/workflows/ci.yml`) всё это идёт на каждый PR: типы, сборка,
маршруты nginx и все наборы на обоих хранилищах.

Новый набор — файл в `tests/suites/` и строка в `SUITES` в `tests/run.mjs`
(окружение сайта и нужные заглушки). Набор пишет «OK/FAIL» и выходит с кодом 1
при провале; помощники — `tests/lib/http.mjs` (сессия с cookie, текст
страницы), `tests/lib/store.mjs` (чтение хранилища), `tests/lib/hbb.mjs`.
