# Приём оплаты через ЮKassa

Продажа подписок настроена на ЮKassa: карты, СБП, кошелёк. Резервный режим
`manual` (счёт подтверждает администратор) остаётся для юрлиц и для случаев,
когда касса ещё не подключена.

## 1. Что получить в ЮKassa

Личный кабинет ЮKassa → **Интеграция → Ключи API**:

- `shopId` — идентификатор магазина;
- секретный ключ (боевой или тестовый).

Тестовый магазин работает без договора — на нём можно проверить всю цепочку.

## 2. Переменные окружения

```env
REMIT_BILLING_PROVIDER=yookassa
YOOKASSA_SHOP_ID=123456
YOOKASSA_SECRET_KEY=live_XXXXXXXXXXXXXXXXXXXX
YOOKASSA_RETURN_URL=https://remit.su/kabinet/podpiska
```

Секретный ключ хранится только в `.env` на сервере: в репозиторий, в образ и в
клиент он не попадает.

## 3. Уведомления

ЮKassa → **Интеграция → HTTP-уведомления**:

```text
https://remit.su/api/v1/billing/webhook/yookassa
```

События: `payment.succeeded`, `payment.canceled`.

Телу уведомления мы не доверяем: из него берётся только идентификатор платежа,
после чего статус перезапрашивается в API ЮKassa (`lib/billing.ts`,
`fetchYookassaPayment`). Подделать активацию подписки, отправив запрос на
вебхук, нельзя.

Если уведомление не дошло, подписка всё равно включится: при открытии страницы
`/kabinet/podpiska` сервис перепроверяет статусы ожидающих платежей напрямую
(`syncPendingPayments`).

## 4. Как проходит оплата

```text
Кабинет → POST /api/v1/billing/checkout
        → создаём платёж в ЮKassa (Idempotence-Key, чек по 54-ФЗ)
        → пользователь на странице оплаты ЮKassa
        → возврат на /kabinet/podpiska
        → вебхук payment.succeeded → подписка активна
```

Продление считается от текущей даты окончания, если она ещё не прошла: оплата
за месяц во время действующей подписки добавляет месяц, а не обнуляет остаток
(`activateSubscription`).

## 5. Чеки и 54-ФЗ

В запрос на создание платежа передаётся `receipt` с одной позицией:

- наименование: «Подписка RemIT «Профи», 1 мес.»;
- `vat_code: 1` — без НДС;
- `payment_mode: full_prepayment`, `payment_subject: service`.

`vat_code` нужно привести к вашей системе налогообложения: 1 — без НДС,
2 — НДС 0%, 3 — 10%, 4 — 20%. Если чеки выбивает ваша касса, а не ЮKassa,
блок `receipt` из `lib/billing.ts` уберите.

## 6. Тарифы

Цены заданы в копейках в `lib/plans.ts` — это единственное место, где их нужно
менять: витрина, кабинет, оферта и создание платежа читают оттуда.

```ts
priceMonthly: 89000,   // 890 ₽ в месяц
priceYearly: 890000,   // 8 900 ₽ в год
```

## 7. Ручное подтверждение (юрлица)

Для оплаты по счёту:

```bash
curl -X POST https://remit.su/api/v1/billing/confirm \
  -H "Authorization: Bearer $REMIT_SERVICE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"paymentId":"pay_xxxxxxxx"}'
```

Подписка включается сразу, платёж помечается оплаченным.

## 8. Перед первым боевым платежом

- заполните реквизиты в `/dokumenty/oferta` и `/dokumenty/politika` —
  ЮKassa проверяет оферту и политику обработки данных при подключении;
- проверьте цепочку на тестовом магазине: оплата, вебхук, активация, продление;
- убедитесь, что `REMIT_SERVICE_TOKEN` и `REMIT_AUTH_SECRET` заданы
  случайными значениями, а не значениями по умолчанию.
