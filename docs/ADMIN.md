# Админка

Раздел `/admin` — управление сервисом и его API: пользователи, подписки,
платежи, активные сессии, устройства и настройки тарификации.

## Кто получает доступ

1. Почта из переменной `REMIT_ADMIN_EMAILS` (через запятую) — так входят
   в свежую установку, где роль `admin` ещё некому выдать;
2. роль `admin` в базе — выдаётся из самой админки на странице «Пользователи».

Всё остальное закрыто: обычный пользователь и неавторизованный запрос получают
`403`. В шапке кабинета у администратора появляется ссылка «Админка».

```env
REMIT_ADMIN_EMAILS=admin@remit.su
```

## Что можно делать

### Обзор

Пользователи, активные подписки, ежемесячная выручка по активным тарифам,
поступления за 30 дней, сессии прямо сейчас, устройства, израсходованное
сегодня время. Здесь же — проверка связи с панелью `rustdesk-api` и сводка
конфигурации.

### Пользователи

Поиск по почте и имени. Для каждого аккаунта видно тариф, срок действия,
расход за сегодня и число устройств. Действия:

- **выдать пробный период** — тариф и срок (до 30 дней) прямо из карточки
  пользователя. Клиент сам активировать пробу не может: на сайте только форма
  заявки, доступ открывает администратор;
- **выдать подписку** — тариф и срок вручную: оплата по счёту, компенсация,
  тестовый доступ, партнёрские условия. Для корпоративного тарифа тут же
  указывается согласованное число одновременных сессий;
- **изменить число одновременных сессий** — поле «Одновременных сессий» у
  действующей подписки: меняется без смены тарифа и срока, кнопка «Вернуть к
  тарифу» возвращает значение из тарифной сетки;
- **отменить подписку** — сразу возвращает аккаунт на бесплатный тариф;
- **обнулить расход за сегодня** — «подарить» часы или снять ошибочное
  списание, не выдавая подписку;
- **сделать админом / снять админа** — роль в базе.

### Платежи и подписки

Последние платежи всех пользователей и активные подписки. Ожидающий платёж
можно подтвердить вручную (включает подписку) или отменить. Оплаченный платёж
отменить нельзя — для возврата оформляйте его в ЮKassa.

### Сессии

Всё, что идёт прямо сейчас: кто платит за сессию, управляющая и управляемая
стороны, длительность. Кнопка «Завершить» закрывает учётную запись сессии, а
сам разрыв произойдёт на ближайшем heartbeat — до 15 секунд, тем же способом,
что и при исчерпании лимита.

### Устройства

Последние устройства по активности, их владельцы и отвязка от аккаунта.

### Заявки

Заявки на пробный период, оставленные на странице «Пробный период»: контакты,
компания, число устройств и задача. Из карточки заявки пробный период выдаётся
одной кнопкой — выбираете тариф и срок (до 30 дней). Если аккаунта с такой
почтой ещё нет, админка подскажет попросить клиента зарегистрироваться.

Пробный период всегда выдаёт администратор: самостоятельной активации у
клиента нет. Это сознательное ограничение — безлимитный удалённый доступ на
две недели слишком привлекателен для тех, кто звонит «из службы безопасности
банка», поэтому каждую заявку кто-то смотрит глазами.

### Обращения

Обращения в поддержку, отправленные из кабинета. Писать может только вошедший
пользователь, поэтому почта и имя берутся из аккаунта: обратиться от чужого
имени нельзя, и капча не нужна. С одного аккаунта принимаем не больше десяти
обращений в сутки.

В карточке видны тема, текст, приложенные снимки экрана и почта автора.
Картинки открываются по клику и доступны только автору обращения и
администраторам: на скриншоте может быть видно что угодно — от адресной книги
до чужого рабочего стола, поэтому ссылка не работает «для всех, кто её знает».
Принимаем PNG, JPEG, WebP, GIF и HEIC, до пяти файлов по 10 МБ; формат
проверяется по первым байтам файла, а не по расширению. Ответ пишется прямо здесь и
появляется у клиента в разделе «Поддержка» — обращение при этом само переходит
в статус «отвечено». Кнопки «В работе» и «Закрыть» меняют только статус.

Личных мессенджеров в интерфейсе нет намеренно: переписка должна оставаться в
компании, а не в личном аккаунте сотрудника. Если настроены
`REMIT_TELEGRAM_BOT_TOKEN` и `REMIT_TELEGRAM_CHAT_ID`, о новом обращении
приходит уведомление в бот поддержки.

### Обновления

Выпуски клиента: версия, канал, обязательность, заметки и файлы сборок.
Опубликованный выпуск сразу попадает в проверку обновлений, на страницу
загрузок и на собственную страницу `/obnovlenie/<версия>`. Черновик не виден
никому. Подробно — `docs/UPDATES.md`.

### Настройки

Меняются на лету, без перезапуска (применяются в течение 10 секунд):

| Настройка | Смысл |
|---|---|
| Бесплатный лимит | часы в сутки для бесплатного тарифа |
| Регистрация | открыта или закрыта; вход существующих аккаунтов не затрагивается |
| Сообщение в кабинете | баннер о работах, аварии или акции |
| Настройки клиентов | значения, которые сервер рассылает всем клиентам (адреса серверов, правила доступа); применяются за 15 секунд |

Ниже — конфигурация развёртывания (домен, серверы, провайдер оплаты,
факт наличия секретов). Она задаётся в `server/.env` и требует перезапуска.
Значения секретов не показываются.

## То же самое через API

Все действия доступны по HTTP — для скриптов и интеграций. Авторизация:
cookie администратора или сервисный токен `REMIT_SERVICE_TOKEN`.

| Метод и путь | Действие |
|---|---|
| `GET /api/v1/admin/overview` | сводка и состояние панели |
| `GET /api/v1/admin/users?q=&limit=&offset=` | список пользователей |
| `POST /api/v1/admin/users` | `{userId, role}` — смена роли |
| `GET /api/v1/admin/subscriptions` | активные подписки |
| `POST /api/v1/admin/subscriptions` | `{action:"grant"\|"trial"\|"limits"\|"cancel", userId, plan, months, days, concurrent}` |
| `GET /api/v1/admin/payments?limit=` | последние платежи |
| `GET /api/v1/admin/tickets` | обращения в поддержку с почтой автора |
| `POST /api/v1/admin/tickets` | `{id, answer, status}` — ответ и смена статуса |
| `POST /api/v1/admin/payments` | `{paymentId, action:"confirm"\|"cancel"}` |
| `GET /api/v1/admin/sessions` | активные сессии |
| `POST /api/v1/admin/sessions` | `{hostId, connId}` — завершить сессию |
| `GET /api/v1/admin/devices?limit=` | устройства |
| `POST /api/v1/admin/devices` | `{rustdeskId, action:"bind"\|"unbind", userId}` |
| `GET /api/v1/admin/settings` | текущие настройки |
| `POST /api/v1/admin/settings` | `{key, value}` — изменить настройку |
| `POST /api/v1/admin/usage` | `{userId}` или `{subjectKey}` — обнулить расход |
| `GET /api/v1/admin/releases` | выпуски клиента, включая черновики |
| `POST /api/v1/admin/releases` | создать или изменить выпуск |
| `DELETE /api/v1/admin/releases?id=` | удалить выпуск |
| `GET /api/v1/admin/policy` | текущая политика клиентов |
| `POST /api/v1/admin/policy` | `{options}` — разослать настройки всем клиентам |
| `GET /api/v1/admin/leads` | заявки с сайта |
| `POST /api/v1/admin/leads` | `{id, action:"trial"\|"status"\|"note"}` — выдать пробный период или сменить статус |

Пример: выдать тариф «Профи» на 3 месяца из скрипта.

```bash
curl -X POST https://remit.su/api/v1/admin/subscriptions \
  -H "Authorization: Bearer $REMIT_SERVICE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action":"grant","userId":"usr_xxx","plan":"pro","months":3}'
```

Корпоративный клиент с 40 одновременными сессиями на год:

```bash
curl -X POST https://remit.su/api/v1/admin/subscriptions \
  -H "Authorization: Bearer $REMIT_SERVICE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action":"grant","userId":"usr_xxx","plan":"corporate","months":12,"concurrent":40}'
```

Позже число сессий меняется отдельно, не трогая срок:

```bash
curl -X POST https://remit.su/api/v1/admin/subscriptions \
  -H "Authorization: Bearer $REMIT_SERVICE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action":"limits","userId":"usr_xxx","concurrent":60}'
```

Значение `null` в `concurrent` возвращает лимит, заданный тарифом.

Пробный период на 30 дней конкретному пользователю:

```bash
curl -X POST https://remit.su/api/v1/admin/subscriptions \
  -H "Authorization: Bearer $REMIT_SERVICE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"action":"trial","userId":"usr_xxx","plan":"pro","days":30}'
```

## Безопасность

- сервисный токен даёт полный доступ к админскому API — храните его как
  пароль и не передавайте в браузер;
- права администратора выдавайте точечно: из админки видны все аккаунты,
  платежи и активные сессии;
- содержимое удалённых сессий админка не показывает и показать не может —
  оно шифруется между устройствами.
