# Аккаунт, вход в клиенте и адресные книги

Аккаунт один — на сайте. Им входят в личный кабинет и в клиент RemIT (кнопка
«Войти» в клиенте). Всё, что раньше жило в панели rustdesk-api — пользователи,
токены клиента, адресные книги, сведения об устройствах, журналы, — хранит и
показывает сайт.

## Вход в клиенте

`POST /api/login` принимает почту и пароль от кабинета. Защита от перебора та
же, что на странице входа, и счётчик общий: 5 ошибок на почту и 30 на адрес за
15 минут.

После входа клиент получает токен — JWT HS256 с полями `user_id` и `exp`,
подписанный `JWT_KEY`. Этот ключ знает и hbbs: при `MUST_LOGIN=Y` он соединяет
только клиентов с действующим токеном. Сайт хранит хеш каждого токена
(`client_tokens`), поэтому вход можно завершить:

- в клиенте — «Выйти»;
- в кабинете — «Устройства» → «Где выполнен вход в клиенте»;
- в админке — «Входы в клиенте» или карточка пользователя;
- сброс пароля завершает все входы сам.

Срок входа — `REMIT_CLIENT_TOKEN_TTL` (30 дней). Компьютер, с которого вошли,
привязывается к аккаунту: на нём сразу действует тариф.

## Адресные книги

У каждого аккаунта есть личная книга — в клиенте это «Моя адресная книга».
Можно завести общие книги и открыть к ним доступ другим аккаунтам по почте:

| Уровень | Что можно |
|---|---|
| чтение | видеть записи и метки |
| чтение и запись | добавлять и менять записи и метки |
| полный доступ | ещё и удалять |

Настройки книги (название, доступ, удаление) — только у владельца. Книга с
записями, метками и доступами хранится одним документом (`address_books`).

Работать с книгами можно в клиенте и в кабинете («Адресная книга») — это одни
и те же данные. Администратор видит и правит любую книгу в админке. Кнопка
«Добавить все мои устройства» заносит в книгу устройства аккаунта разом.

Клиент поддерживает и старый формат (`GET/POST /api/ab` — вся книга одной
строкой): он работает с личной книгой.

## Устройства и журналы

- `POST /api/sysinfo` — клиент присылает имя компьютера, пользователя ОС,
  процессор, память, версию. Видно в кабинете и в админке.
- `POST /api/heartbeat` — учёт времени (`docs/QUOTA.md`); если сведений о
  системе ещё нет, сайт просит их прислать.
- `POST /api/audit/conn` — журнал подключений: кто, откуда, какой вид
  подключения. Отсюда же сайт узнаёт, кому записывать время.
- `POST /api/audit/file` — журнал передачи файлов. В кабинете — «История»,
  в админке — «Передача файлов».
- `POST /api/audit/alarm` — тревоги: подбор пароля, подключение с адреса вне
  белого списка. В кабинете — «История», в админке — «Тревоги».

Журналы хранятся год; администратор может удалить запись или всё старше N
дней. Действующие входы в клиенте не удаляются — их сначала завершают.

## Команда и группы устройств

Участники команды видят устройства друг друга во вкладке «Доступные
устройства» клиента. Команду заводит пользователь в кабинете («Команда») и
приглашает коллег по почте их аккаунтов; устройства видны только после того,
как приглашение принято. Владелец раскладывает устройства по группам — по ним
клиент группирует список. Один аккаунт — одна команда. Администратор видит все
команды и может распустить команду или исключить участника.

## Вход через VK ID

Кнопка «VK ID» на страницах входа и регистрации и в клиенте (появляется, когда
задан `REMIT_VK_CLIENT_ID`). Протокол — OAuth 2.1 с PKCE (`lib/vk.ts`).

- Профиль VK уже привязан — входим в этот аккаунт.
- Не привязан, в VK есть почта и аккаунта с ней нет — заводим аккаунт без
  пароля (пароль можно задать через «Забыли пароль»).
- Аккаунт с такой почтой уже есть — не входим: владелец входит паролем и
  привязывает VK в «Профиле». Почта сайта не подтверждается, и иначе профиль
  VK с чужой почтой открыл бы чужой аккаунт.
- В клиенте: `POST /api/oidc/auth` возвращает ссылку, клиент открывает её в
  браузере и опрашивает `/api/oidc/auth-query`, пока вход не завершится.

## Веб-клиент (бета)

`/webclient` — RustDesk для браузера (сборка из lejianwen/rustdesk-api).
Входит в любой платный тариф, на бесплатном его нет. Доступ проверяется на
всех уровнях:

- **сервер (главное)**: hbbs сообщает сайту, что соединение запрошено по
  WebSocket, то есть из браузера. Такое соединение сайт пропускает только с
  токеном платного подписчика или гостевым токеном на это самое устройство.
  Поэтому ограничение не обойти ни своим веб-клиентом, ни копией нашей
  страницы: без токена hbbs откажет с текстом «Веб-клиент доступен на любом
  платном тарифе». Нужен свой образ сервера — со стоковым hbbs этой проверки нет;
- страницу `/webclient` сайт отдаёт только вошедшему с платной подпиской
  (или гостю по живой ссылке), остальных ведёт на вход или к тарифам;
- вход в самом веб-клиенте и его адресная книга (`/api/server-config`)
  требуют платного тарифа;
- гостевые ссылки создаёт только платный аккаунт, и работают они, пока у
  владельца действует подписка. Гость получает токен только на одно
  устройство (scope `share`): API и данные владельца по нему недоступны, а
  при отзыве ссылки токен гаснет.

Подписчику сайт входит в веб-клиент сам: токен кладёт `/webclient-config/index.js`.
Веб-клиент подключается под общим ID «web», поэтому аккаунт для учёта времени
берётся из проверки квоты hbbs (токен входа из punch hole, нужен свой образ);
без неё время пишется владельцу управляемого устройства. Мы убрали
из него аналитику Firebase, опрос публичных серверов rustdesk.com и загрузку
шрифтов напрямую из Google (шрифты идут через сайт), добавили отметку «бета».
Адрес сервера и ключ он получает из `/webclient-config/index.js`, после входа —
личную адресную книгу из `/api/server-config`. С hbbs и hbbr соединяется по
WebSocket через nginx (порты 21118 и 21119 с TLS).

Гостевая ссылка («Кабинет» → «Веб-клиент», вид `https://<домен>/webclient?share=…`):
человек открывает её и сразу подключается к устройству — без аккаунта. Пароль устройства хранится зашифрованным
`REMIT_AUTH_SECRET`; одноразовая ссылка сгорает после первого открытия.

## Блокировка и удаление аккаунта

- Блокировка (админка) запрещает вход на сайте, в клиенте и через VK ID и
  сразу завершает все входы.
- Удаление (админка или «Профиль» владельцем) стирает почту, имя, пароль,
  адресные книги, команду, привязки устройств и VK. Записи об оплатах остаются
  для бухгалтерского учёта. Почту после удаления можно зарегистрировать снова.

## Настройка

```
JWT_KEY=...                    # openssl rand -hex 32; то же значение получает hbbs
REMIT_CLIENT_TOKEN_TTL=2592000 # срок входа в клиенте, секунды
MUST_LOGIN=N                   # Y — соединяться могут только вошедшие (нужен свой образ hbbs)
REMIT_VK_CLIENT_ID=            # вход через VK ID; пусто — выключен
```

`JWT_KEY` не меняйте без нужды: после смены все входы в клиенте станут
недействительны, и людям придётся войти заново.
