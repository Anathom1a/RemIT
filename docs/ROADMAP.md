# План развития

Порядок отражает то, что раньше упирается в деньги и в поддержку.

## 1. Запуск (готово в этой версии)

- витрина, тарифы, регистрация, личный кабинет;
- учёт бесплатных 3 часов в сутки и принудительный разрыв сессий;
- отказ в новых подключениях на уровне hbbs;
- оплата подписки через ЮKassa, продление и история платежей;
- админка: пользователи, ручная выдача подписок, подтверждение счетов,
  активные сессии, устройства и настройки тарификации на лету;
- сервер обновлений: загрузка сборок в админке, раздача со своего домена,
  проверка версии при запуске клиента и рассылка настроек на все клиенты;
- поисковая оптимизация: карта сайта, микроразметка, посадочные страницы;
- пробный период для компаний с заявкой и выдачей из админки;
- корпоративный тариф с договорной ценой и настраиваемым числом
  одновременных сессий;
- правовые документы: соглашение, политика, согласие, cookie;
- развёртывание одной командой, сборка фирменного клиента;
- автопродление с сохранённой в ЮKassa картой, предупреждением за 3 дня и
  повторными попытками; чеки по 54-ФЗ, включая второй чек полного расчёта;
- ежедневные зашифрованные резервные копии с проверкой восстановления и
  отправкой во внешнее хранилище;
- мониторинг с оповещениями в Telegram и на почту, сторож сайта и
  публичная страница статуса с доступностью за 90 дней;
- несколько ретрансляторов: узлы подключаются из админки и скриптом
  `server/deploy-relay.sh`, клиент получает ретранслятор от сервера.

## 2. Ближайшее

- **Веб-клиент из бета-версии.** Сейчас это сборка RustDesk 1.1.10 для
  браузера из lejianwen/rustdesk-api. Нужны свежая сборка из исходников
  RustDesk, перевод интерфейса и отметка тарифа в самом клиенте.
- **Почта.** Корпоративные ящики на домене (порядок в `docs/EMAIL.md`), затем
  письма из сервиса: подтверждение почты, предупреждение об окончании
  подписки без автопродления и пробного периода.
- **Подсчёт скачиваний** и подпись сборок с проверкой на стороне клиента.
- **Постепенная выкатка.** Доля клиентов, которым предлагается новая версия,
  и политики для групп устройств, а не только общая.

## 3. Следующее

- **Командные тарифы.** Несколько операторов внутри одного аккаунта, общая
  адресная книга, роли. Сейчас корпоративный клиент получает общий лимит
  сессий на аккаунт — следующий шаг в том, чтобы у каждого сотрудника был
  свой вход.
- **Антифрод.** Ограничение на число новых устройств с одного адреса, выявление
  ферм бесплатных аккаунтов.
- **Отчёты.** Выгрузка журнала подключений в CSV для клиента и руководителя.

## 4. Когда появится объём

- выбор ближайшего ретранслятора по географии клиентов (патч hbbs,
  `docs/RELAYS.md`);
- собственные сборки клиента для macOS и мобильных платформ с подписью;
- выделенные инсталляции для корпоративных клиентов;
- партнёрская программа для сервисных компаний.
