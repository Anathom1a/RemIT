# Архитектура RemIT

## Идея

Мы не пишем протокол удалённого доступа с нуля — берём открытое ядро RustDesk
и строим вокруг него продукт: свой бренд, свой сайт, свою тарификацию. Так же
устроены все российские сервисы такого рода.

Работы делятся на три слоя:

| Слой | Что используем | Что пишем сами |
|---|---|---|
| Клиент | RustDesk | название, иконки, вшитые адреса серверов |
| Сервер связи | `hbbs` + `hbbr` (rustdesk-server, ветка `forapi`) | патч проверки лимита перед выдачей соединения |
| Панель и API | `lejianwen/rustdesk-api` | шлюз учёта времени, сайт, кабинет, подписки |

Готовый код закрывает примерно половину задачи: протокол, шифрование, NAT,
адресная книга, веб-клиент. Наша часть — деньги и лимиты.

## Маршруты

| Маршрут | Куда идёт | Зачем |
|---|---|---|
| `/` | RemIT web | витрина, тарифы, кабинет |
| `/api/heartbeat` | RemIT web → rustdesk-api | учёт времени + принудительный разрыв |
| `/api/audit/conn` | RemIT web → rustdesk-api | начало и конец сессии, кто к кому |
| `/api/v1/*` | RemIT web | регистрация, устройства, подписки, квоты |
| `/admin`, `/api/v1/admin/*` | RemIT web | админка и административное API |
| `/api/version/latest`, `/api/v1/updates/*` | RemIT web | сервер обновлений клиента |
| `/api/*` | rustdesk-api | вход клиента, адресная книга, синхронизация |
| `/_admin/`, `/webclient/` | rustdesk-api | панель администратора и веб-клиент |

Сайт и панель делят домен и префикс `/api/`, причём панель забирает его
целиком. Поэтому каждый наш путь внутри `/api/` должен быть отдельно прописан в
`server/nginx/remit.conf` — забыли, и запрос молча уходит в панель и
возвращает 404. Так уже случалось с `/api/version/latest`: маршрут в приложении
был, а в nginx — нет, и проверка обновлений в клиенте не работала.

Чтобы это не повторялось, есть проверка:

```bash
python3 server/nginx/check-routes.py
```

Она разбирает `location` по правилам nginx и сверяет с маршрутами из `app/api`:
каждый путь сайта должен резолвиться на сайт, а вход, адресная книга и
доступные устройства — оставаться за панелью.

Шлюз перед `/api/heartbeat` — ключевое решение всей схемы. Клиент RustDesk
штатно понимает в ответе два поля:

- `disconnect` — список подключений, которые нужно разорвать: так работает
  принудительное завершение сессий по исчерпании лимита;
- `strategy.config_options` — настройки, которые клиент применяет к себе: так
  правки доезжают до всех установленных клиентов за один интервал heartbeat.

Оба механизма штатные, патчить клиент ради них не нужно. Подробности — в
`docs/QUOTA.md` и `docs/UPDATES.md`.

## Состав репозитория

```text
app/           сайт, личный кабинет и API (Next.js App Router)
components/    интерфейс: витрина, кабинет, элементы управления
lib/           конфигурация, тарифы, учёт квот, оплата, хранилище
server/        docker-compose, nginx, Dockerfile, SQL-схема, deploy.sh
client/        ребрендинг клиента и патч лимита для hbbs
docs/          архитектура, тарификация, оплата, развёртывание
```

## Хранилище

Интерфейс `lib/store/index.ts` с двумя реализациями:

- `MemoryStore` — JSON-файл, для разработки и демонстраций (`npm run dev`);
- `PostgresStore` — рабочий режим, включается переменной `DATABASE_URL`.

Схема: `server/sql/001_init.sql`, применяется при старте автоматически.
