# Архитектура RemIT

## Идея

Мы не пишем протокол удалённого доступа с нуля — берём открытое ядро RustDesk
и строим вокруг него продукт: свой бренд, свой сайт, свою тарификацию. Так же
устроены все российские сервисы такого рода.

Работы делятся на три слоя:

| Слой | Что используем | Что пишем сами |
|---|---|---|
| Клиент | RustDesk | название, иконки, вшитые адреса серверов |
| Сервер связи | `hbbs` + `hbbr` (lejianwen/rustdesk-server, ветка `forapi`) | патч проверки лимита перед выдачей соединения |
| API клиента, сайт | — | вход, адресные книги, сведения об устройствах, аудит, учёт времени, кабинет, админка, подписки |

API, которое клиент RustDesk вызывает у «API-сервера» (вход, адресная книга,
heartbeat, аудит), сайт реализует сам. Отдельной панели rustdesk-api нет:
один аккаунт, одна база, одна админка.

## Схема

```text
          ┌─────────────────────────┐
          │  Клиент RemIT           │
          │  (сборка RustDesk)      │
          └───┬─────────────┬───────┘
              │             │  вход, адресная книга, heartbeat,
   P2P/relay  │             │  сведения о системе, аудит
              │             ▼
     ┌────────▼───────┐   ┌──────────────┐
     │ hbbs / hbbr    │   │  nginx       │
     │ порты 21115-19 │   └──────┬───────┘
     └────────┬───────┘          ▼
              │      ┌──────────────────────────┐
              └─────▶│ RemIT web                │
       /quota/check  │ сайт, кабинет, админка,  │
                     │ API клиента, учёт квот   │
                     └───────────┬──────────────┘
                                 ▼
                            ┌─────────┐
                            │Postgres │
                            └─────────┘
```

hbbs знает ключ `JWT_KEY`, которым сайт подписывает токены входа: при
`MUST_LOGIN=Y` он соединяет только клиентов, вошедших в аккаунт. Патчи hbbs
(свой образ): проверка суточного лимита по токену входа и приём служебных
команд из админки по `REMIT_SERVICE_TOKEN` (порты 21115 и 21117).

Фоновые задачи идут внутри сайта (`instrumentation.ts` → `lib/scheduler.ts`):
раз в минуту мониторинг (`lib/monitoring.ts`), раз в 10 минут автопродление
и чеки, раз в 5 минут сверка ретрансляторов. За самим сайтом следит сторож —
контейнер `watchdog` (`docs/MONITORING.md`).

Ретрансляторов может быть несколько: основной hbbr и отдельные узлы
(`server/relay`, `server/deploy-relay.sh`). Клиент адрес ретранслятора не
хранит — его назначает hbbs из списка, который ведётся в админке и
передаётся hbbs командой `rs` (`lib/relays.ts`). Подробно — `docs/RELAYS.md`.

## Маршруты

Весь домен обслуживает сайт. API клиента RustDesk:

| Маршрут | Зачем |
|---|---|
| `/api/login`, `/api/logout`, `/api/currentUser`, `/api/login-options` | вход в клиенте почтой и паролем кабинета |
| `/api/heartbeat` | учёт времени, принудительный разрыв, рассылка настроек |
| `/api/sysinfo`, `/api/sysinfo_ver` | сведения о системе устройства |
| `/api/audit/conn`, `/api/audit/file`, `/api/audit/alarm` | журнал подключений и передачи файлов |
| `/api/ab`, `/api/ab/*` | адресные книги: личная, общие, метки, доступ |
| `/api/users`, `/api/peers`, `/api/device-group/accessible` | вкладка «Доступные устройства»: вы и ваша команда, группы устройств |
| `/api/login-options`, `/api/oidc/auth`, `/api/oidc/auth-query` | вход в клиенте через VK ID |
| `/webclient`, `/webclient-config/index.js`, `/api/server-config`, `/api/shared-peer` | веб-клиент (бета, платные тарифы) и гостевые ссылки |
| порты 21118, 21119 (nginx, TLS) | WebSocket веб-клиента к hbbs и hbbr |
| `/api/version/latest`, `/api/v1/updates/*` | сервер обновлений клиента |

Кабинет и админка: `/kabinet`, `/admin`, `/api/v1/*`. Подробности про вход и
адресные книги — [ACCOUNTS.md](ACCOUNTS.md).

Проверка, что nginx отдаёт сайту все его пути и что у каждого пути, который
вызывает клиент, есть маршрут:

```bash
python3 server/nginx/check-routes.py
```

Клиент RustDesk штатно понимает в ответе на heartbeat три поля:

- `disconnect` — список подключений, которые нужно разорвать: так работает
  принудительное завершение сессий по исчерпании лимита;
- `strategy.config_options` — настройки, которые клиент применяет к себе: так
  правки доезжают до всех установленных клиентов за один интервал heartbeat;
- `sysinfo` — просьба прислать сведения о системе.

Все механизмы штатные, патчить клиент ради них не нужно. Подробности — в
`docs/QUOTA.md` и `docs/UPDATES.md`.

## Состав репозитория

```text
app/           сайт, личный кабинет и API (Next.js App Router)
components/    интерфейс: витрина, кабинет, элементы управления
lib/           конфигурация, тарифы, учёт квот, оплата, хранилище
server/        docker-compose, nginx, Dockerfile, SQL-схема, deploy.sh
client/        ребрендинг клиента и патч лимита для hbbs
docs/          архитектура, тарификация, оплата, развёртывание
```

## Хранилище

Интерфейс `lib/store/index.ts` с двумя реализациями:

- `MemoryStore` — JSON-файл, для разработки и демонстраций (`npm run dev`);
- `PostgresStore` — рабочий режим, включается переменной `DATABASE_URL`.

Схема: `server/sql/001_init.sql`, применяется при старте автоматически.
