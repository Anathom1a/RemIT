# Ретрансляторы

Если два компьютера не могут соединиться напрямую (NAT, корпоративный
файрвол), трафик идёт через ретранслятор — hbbr. Один hbbr работает на основном
сервере. Когда пользователей станет больше или понадобятся узлы ближе к
клиентам, добавляются отдельные ретрансляторы на других машинах.

## Как это устроено

- **Клиент адрес ретранслятора не знает и поменять его не может.** В сборке
  RemIT настройка `relay-server` закреплена пустой. Адрес для каждого
  соединения назначает hbbs основного сервера.
- **hbbs распределяет соединения по кругу** между включёнными узлами и каждые
  3 секунды проверяет, отвечают ли они. Узел, который не отвечает, временно
  исключается из раздачи и возвращается сам, когда снова заработает.
- **Список узлов ведётся в админке** («Ретрансляторы»). После каждого
  изменения сайт передаёт его hbbs командой `rs`. После перезапуска hbbs
  список забывается (остаётся только `RELAY` из `.env`), поэтому сайт раз в
  пять минут сверяет список и при расхождении передаёт его снова.
- **Отдельному узлу нужен только открытый ключ** основного сервера: hbbr
  пропускает только клиентов с этим ключом. Закрытый ключ `id_ed25519` на узлы
  не копируется.
- **Токен команд у каждого узла свой.** Им админка узнаёт нагрузку и управляет
  ограничениями скорости. Если узел взломают, этим токеном нельзя управлять ни
  другими узлами, ни основным сервером. Хранится токен зашифрованным ключом
  `REMIT_AUTH_SECRET`.
- **Веб-клиент** соединяется с ретранслятором по `wss://<узел>:21119`, поэтому
  узлу нужны доменное имя и сертификат. Скрипт установки выпускает сертификат
  Let's Encrypt и сам его продлевает.

Лимит бесплатного тарифа, вход и веб-клиент проверяет hbbs основного сервера
ещё до того, как назначен ретранслятор, поэтому узлам не нужны ни база, ни
доступ к сайту.

## Подключить новый ретранслятор

1. Заведите машину с белым IP (Ubuntu 22.04/24.04, от 1 ядра и 1 ГБ памяти;
   главное — канал: одно соединение занимает от 1 до 10 Мбит/с) и
   A-запись, например `relay1.remit.su`.
2. Админка → «Ретрансляторы» → «Добавить»: адрес, название, регион. Узел
   добавится выключенным, а админка покажет команду установки.
3. Скопируйте на машину репозиторий (или только каталог `server/` и
   `server/deploy-relay.sh`) и выполните показанную команду:

   ```bash
   sudo bash server/deploy-relay.sh \
     --domain relay1.remit.su \
     --key '<открытый ключ сервера>' \
     --token <токен узла>
   ```

   Скрипт ставит Docker, выпускает сертификат, открывает порты в `ufw` и
   запускает `server/relay/docker-compose.yml` (hbbr + nginx).
4. В админке у узла должны загореться обе отметки: «ретрансляция» и
   «веб-клиент (TLS)». Нажмите «Включить».

Порты узла: `21117/tcp` (ретрансляция), `21119/tcp` (веб-клиент), `80` и `443`
(выпуск сертификата и клиент в режиме WebSocket).

Образ по умолчанию — свой образ сервера из GHCR
(`build-server-image.yml`). Если пакет приватный, сначала выполните на узле
`docker login ghcr.io`. Со стоковым образом `rustdesk/rustdesk-server-s6` узел
тоже работает (`--image rustdesk/rustdesk-server-s6:latest`), но команды и
нагрузка в админке будут недоступны.

## Обслуживание

- **Вывести узел на работы**: «Выключить». Новые соединения пойдут через другие
  узлы, текущие продолжатся до конца. После работ — «Включить».
- **Нагрузка и ограничения**: «Команды узла» → `usage` (текущие соединения),
  `total-bandwidth`, `single-bandwidth`, `limit-speed`, блокировки адресов.
  Постоянные ограничения задаются в `server/relay/.env` на узле
  (`TOTAL_BANDWIDTH`, `SINGLE_BANDWIDTH`, `LIMIT_SPEED`, Мбит/с).
- **Удалить узел**: «Удалить» в админке, затем на машине
  `docker compose -f server/relay/docker-compose.yml down`.
- **Ретранслятор основного сервера** удалить нельзя, но можно выключить: тогда
  весь ретранслируемый трафик пойдёт через отдельные узлы. Хотя бы один узел
  всегда остаётся включённым.
- Узлы, раз выключенные в админке, после перезапуска hbbs в раздачу не
  вернутся: сверка передаст список из админки.

## Чего пока нет

hbbs раздаёт узлы по кругу и не учитывает, где находятся клиенты. Выбор
ближайшего узла по географии требует доработки hbbs (патч функции
`get_relay_server`, у которой уже есть адреса обеих сторон). Это следующий
шаг, когда узлы появятся в разных регионах.
