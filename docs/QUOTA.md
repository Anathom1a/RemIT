# Лимит 3 часа в сутки: как устроен

## Правило

Бесплатный тариф — **3 часа активного удалённого управления в сутки на аккаунт**.
Сутки считаются по московскому времени, счётчик обнуляется в 00:00.

Значение задаётся переменной `REMIT_FREE_SECONDS_PER_DAY` (по умолчанию 10800).

## Откуда сервер знает, сколько времени идёт сессия

Клиент RustDesk каждые 15 секунд отправляет на API-сервер heartbeat:

```json
{ "id": "741208365", "uuid": "...", "ver": 1002000, "conns": [7, 9] }
```

`conns` — идентификаторы активных входящих подключений. Пока список не пуст,
устройством кто-то управляет прямо сейчас. Наш шлюз (`app/api/heartbeat`)
принимает эти запросы раньше панели и начисляет время: разница между двумя
heartbeat-ами, но не больше `REMIT_MAX_TICK_SECONDS` (30 секунд) — защита от
перевода часов и длинных пауз.

Аудит подключений (`app/api/audit/conn`) даёт вторую половину картины: в событии
`action: new` есть `peer_id` — идентификатор управляющей стороны. Благодаря ему
время записывается тому, кто подключался, а не тому, к кому подключались.

## Кому записывается время

`lib/quota.ts`, функция `resolveSubject`:

1. Управляющее устройство привязано к аккаунту → расход идёт аккаунту (`user:<id>`).
2. Управляющее устройство известно, но не привязано → расход идёт устройству
   (`device:<id>`), у него свой бесплатный лимит.
3. Управляющая сторона неизвестна (аудит не дошёл) → расход идёт владельцу
   управляемого устройства, иначе самому устройству.

Две параллельные сессии расходуют лимит вдвое быстрее — это осознанное решение:
иначе один аккаунт обслуживал бы весь отдел поддержки.

## Как лимит применяется

Два независимых рычага.

### 1. Разрыв активной сессии (основной)

Если после начисления времени лимит исчерпан, шлюз добавляет в ответ heartbeat:

```json
{ "disconnect": [7] }
```

Клиент RustDesk штатно обрабатывает это поле и разрывает указанные подключения.
Модифицировать клиент не нужно — достаточно, чтобы он смотрел на наш API-сервер.
Реакция занимает не больше одного интервала heartbeat, то есть до 15 секунд.

### 2. Отказ в новом подключении (патч hbbs)

`client/patches/hbbs-quota-hook.py` встраивает в `hbbs` проверку перед выдачей
punch hole: сервер спрашивает `/api/v1/quota/check` и при исчерпанном лимите
возвращает клиенту сообщение вместо соединения. Без этого пользователь мог бы
переподключаться каждые 15 секунд.

Если служба квот недоступна, hbbs пропускает подключение: отказ в обслуживании
из-за сбоя биллинга хуже, чем неучтённая сессия.

## Границы реализации

`hbbs` в запросе punch hole не сообщает идентификатор управляющей стороны —
в протоколе его нет. Поэтому проверка на этом уровне опирается на управляемое
устройство и его владельца, а точный учёт делает шлюз heartbeat. Практический
вывод: просите операторов привязывать свои устройства в кабинете — тогда и учёт,
и отказы работают по их аккаунту. Полное решение (сопоставление с учётными
записями панели и передача токена) — в `docs/ROADMAP.md`.

## Что видит пользователь в клиенте

Фирменная сборка показывает карточку с остатком времени или сроком подписки
на обоих экранах: в главном окне на компьютере и на экране подключения на
телефоне. Клиент раз в минуту обращается к открытому маршруту:

```bash
curl -s -X POST https://remit.su/api/v1/client/state \
  -H "Content-Type: application/json" \
  -d '{"id":"741208365","uuid":"<uuid клиента>"}'
```

Ответ содержит готовую строку для показа и ссылки, куда вести пользователя:

```json
{
  "message": "Осталось сегодня 2 ч 14 мин",
  "exhausted": false,
  "usedSeconds": 2760,
  "limitSeconds": 10800,
  "expiresAtText": null,
  "cabinetUrl": "https://remit.su/kabinet",
  "tariffUrl": "https://remit.su/tarify"
}
```

Сервисный токен здесь не нужен — он не должен лежать в клиенте. Вместо этого
сервер сверяет `uuid`: если для указанного идентификатора записан другой,
запрос отклоняется, поэтому по чужому ID остаток не посмотреть. Персональных
данных в ответе нет.

Состояния строки: остаток бесплатного времени, «Тариф «Профи» до 19.10.2026»,
«Пробный период до 03.10.2026» и «Бесплатные 3 ч на сегодня израсходованы» —
в последнем случае ссылка из карточки ведёт на страницу тарифов.

## Проверка вручную

```bash
# состояние квоты устройства (нужен сервисный токен)
curl -s -H "Authorization: Bearer $REMIT_SERVICE_TOKEN" \
  "https://remit.su/api/v1/quota/state?device=741208365" | jq

# решение для hbbs
curl -s -X POST https://remit.su/api/v1/quota/check \
  -H "Authorization: Bearer $REMIT_SERVICE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"id":"741208365"}' | jq
```

Ответ `/api/v1/quota/check`:

```json
{
  "allowed": false,
  "reason": "daily_limit",
  "message": "Бесплатный лимит 3 ч в сутки израсходован. Подписка снимает ограничение: remit.su/tarify",
  "remaining_seconds": 0,
  "plan": "free"
}
```

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `REMIT_FREE_SECONDS_PER_DAY` | `10800` | бесплатный лимит в сутки |
| `REMIT_TZ` | `Europe/Moscow` | часовой пояс суток тарификации |
| `REMIT_MAX_TICK_SECONDS` | `30` | максимальный шаг начисления между heartbeat |
| `REMIT_STALE_SESSION_SECONDS` | `90` | когда молчащая сессия считается завершённой |
