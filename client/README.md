# Фирменный клиент RemIT

Клиент собирается из открытого проекта [RustDesk](https://github.com/rustdesk/rustdesk).
Так же поступают известные российские сервисы удалённого доступа: берут проверенное
ядро и делают собственный продукт — своё название, свои серверы, свою тарификацию.

Есть два пути. Начните с первого, переходите ко второму, когда появится поток
клиентов и понадобится своё имя в интерфейсе.

## Путь 1. Быстрый: конфигурация в имени файла (1 вечер)

RustDesk читает адрес сервера и ключ прямо из имени исполняемого файла:

```text
remit-host=remit.su,key=ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ.exe
```

Пользователь скачивает такой файл — клиент сразу подключается к вашей
инфраструктуре, настраивать ничего не нужно. В интерфейсе останется название
RustDesk, но лимит 3 часа в сутки уже работает: его считает сервер, а не клиент.

Подходит, чтобы запустить продажи и проверить спрос.

## Путь 2. Полный ребрендинг (своё имя, иконка, установщик)

### 1. Получите исходники

```bash
git clone --recursive https://github.com/rustdesk/rustdesk.git
cd rustdesk
```

### 2. Примените фирменные настройки

```bash
python3 /path/to/RemIT.ru/client/patches/brand-client.py . \
  --app-name RemIT \
  --id-server remit.su \
  --relay-server remit.su \
  --api-server https://remit.su \
  --public-key "$(cat /opt/remit/data/rustdesk/id_ed25519.pub)"
```

Скрипт правит `libs/hbb_common/src/config.rs`:

| Что | Зачем |
|---|---|
| `RENDEZVOUS_SERVERS` | клиент ищет ваш ID-сервер, а не публичный сервер RustDesk |
| `RS_PUB_KEY` | клиент проверяет подпись именно вашего сервера |
| `APP_NAME` | название в заголовках окон, путях и журналах |
| `DEFAULT_SETTINGS` | адреса ID-сервера, ретранслятора и API-сервера по умолчанию |

Он же настраивает обновления, чтобы клиент проверял версию при каждом запуске
и предлагал обновиться:

- `libs/hbb_common/src/lib.rs` — адрес проверки указывает на наш сервер;
- `src/common.rs` и `flutter/lib/common.dart` — снимают запрет на проверку
  версий для фирменной сборки (без этого клиент молча не проверяет обновления);
- `flutter/lib/desktop/pages/desktop_home_page.dart` — показывает карточку
  «Доступна новая версия» с кнопкой «Обновить», ссылки ведут на наш сайт.

Как публиковать выпуски — `docs/UPDATES.md`.

### Что клиент показывает пользователю

Скрипт добавляет в главное окно две вещи:

- **логотип — ссылка на сайт**: нажатие открывает `remit.su` в браузере
  (`flutter/lib/common.dart`);
- **карточка тарифа** (`flutter/lib/remit_status.dart`): остаток
  бесплатного времени на сегодня с полосой расхода, либо срок действия
  подписки или пробного периода. Данные берутся раз в минуту с
  `/api/v1/client/state`; если сайт недоступен, карточка не показывается и
  работе клиента это не мешает.

Карточка встраивается на оба экрана: в главное окно на компьютере
(`desktop/pages/desktop_home_page.dart`, под полем пароля) и на экран
подключения на телефоне (`mobile/pages/connection_page.dart`, под полем ID).
Там же на Android включается предложение обновиться — в фирменной сборке оно
по умолчанию скрыто, как и на компьютере. На iOS обновления остаются за
App Store, поэтому условие сохранено.

Тексты карточки формирует сервер — в клиенте нет ни логики тарифов, ни
переводов, поэтому менять условия можно без пересборки.

Важно: `api-server` должен указывать на сайт (`https://remit.su`), потому что
именно туда клиент шлёт heartbeat и аудит подключений — на этих запросах
построен учёт бесплатных 3 часов в сутки.

### 3. Замените оформление

- `res/` и `flutter/assets/` — иконки приложения и установщика;
- `res/setup.nsi`, `res/msi/` — тексты установщика для Windows;
- `flutter/lib/**` — подписи в интерфейсе, ссылки на поддержку и сайт.

### 4. Соберите

Пошагово — в [`docs/BUILD-CLIENT.md`](../docs/BUILD-CLIENT.md): окружение для
Windows, macOS и Linux, сборка, подпись, проверка и публикация выпуска.

Коротко: `client/prepare-sources.sh` готовит исходники с правками,
`python3 build.py --flutter` собирает, `client/publish-release.sh` загружает
готовые файлы на сайт и публикует выпуск.

Подписывайте Windows-сборку сертификатом организации: без подписи SmartScreen
будет пугать клиентов при каждой установке.

### 5. Выложите файлы

Страница `/skachat` на сайте ведёт на `/api/download/<файл>`. Настройте этот
маршрут на выдачу ваших сборок из объектного хранилища или каталога на сервере.

## Обязательства по лицензии

RustDesk распространяется по AGPL-3.0. Это не запрещает коммерческий сервис и
собственный бренд, но обязывает:

- опубликовать исходный код вашей изменённой версии клиента и сервера;
- сохранить лицензию AGPL-3.0 в составе дистрибутива;
- отметить, что именно вы изменили.

Страница `/dokumenty/licenzii` на сайте уже готова под эти ссылки — заполните её
адресами своих публичных репозиториев.

## Что клиент патчить не нужно

Лимит бесплатного использования намеренно считается на сервере:

- клиент шлёт heartbeat каждые 15 секунд со списком активных подключений;
- сайт считает время и, когда лимит исчерпан, отвечает списком `disconnect`;
- клиент разрывает эти сессии сам — это штатное поведение RustDesk;
- `hbbs` дополнительно отклоняет новые подключения (патч
  `patches/hbbs-quota-hook.py`).

Так же работают и настройки: сервер отдаёт их в ответе heartbeat полем
`strategy`, клиент применяет их сам. Поэтому изменить адрес сервера или правила
доступа на всех установленных клиентах можно из админки, не пересобирая
клиент.

Поэтому даже немодифицированный клиент, настроенный на ваши серверы, подчиняется
тарифу. Патчить клиент ради тарификации не требуется — только ради бренда.
